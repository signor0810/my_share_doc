主題檔案 (profiles)：五類，含一個反轉架構的發現

2026-09-26 · 交互層 S1 的本體 · 設計文件，未實作

專案擁有者指定三個新方向，使 profile 從三類擴為五類。 其中一類（vendor_watch）反轉了架構 v2 的目標函數，需回寫 v2。

〇、最重要的發現：目標函數是 profile 屬性，不是普遍真理

架構 v2 §M.4 定調：「News 的意義在於檢測，得到最珍貴的一手消息。」

這對 MHS 與 EUV 成立 —— 訊號稀少、藏得深、要靠假設驅動去挖。 但對 vendor_watch（追 OpenAI／Anthropic／Cursor／Qwen 等官方 blog）完全不成立：

偵測成本是零 —— 你早就知道網址。稀缺的是讀完它們並判斷哪些重要。

所以這個 profile 的工作是壓縮與翻譯，不是偵測。

回寫 v2：goal 成為 profile 的欄位，有兩個值：

goal稀缺的是什麼主要風險適用 profile
detect找到訊號漏掉真訊號、收進虛構內容standard_adoption、deep_tech_process、regulatory
compress讀完並排序摘要失真、被公關語言帶走vendor_watch、research_frontier

兩者的整個管線行為不同，不只是參數不同。compress 型不需要 ② Hypothesize 與方向迴圈（來源固定），但需要一個 detect 型不需要的階段：忠實度查核。

一、vendor_watch · AI 實驗室與產品動態

一個主題，九個錨點 —— 不是九個主題。 否則 dashboard 會有九列講同一件事，你也會收到九封信。

錨點清單本身是要維護的資產 —— 網域會變（Qwen 的 blog 就在 GitHub Pages 上）。 每期記錄各錨點命中數，連續兩期 0 命中觸發錨點複查（可能是網域搬了，不是沒發文）。

兩個必須反轉的預設

1. hard_filters.pr_wire 必須關掉。 官方發布公告在定義上就是產品發布通知。在這個 profile 裡， 你要讀的東西正好是其他 profile 要濾掉的東西。 開著它會把整個主題濾成空的。

2. Auth 階梯會塌掉，需要換判準。 九個來源全是 vendor_doc，全給 95 分等於沒有區分度。 在這個 profile 內，Auth 改由可驗證性決定：

子級判準Auth
verifiable附可重現的基準、具體數字、或可取用的模型／API95
demonstrated有示範或案例，但無可重現方法70
announced只有能力敘述，無數字無示範45
marketing形容詞堆疊，無任何可檢查內容20

marketing 在其他 profile 是邊緣狀況，在這裡是常態工作量。

翻譯的品質防線（新增，compress 型專屬）

中文摘要會靜默引入錯誤，而錯誤的翻譯與幻覺對讀者的傷害相同。

防線 5 · 可回溯翻譯：任何能力宣稱或數字，中文摘要旁必須保留原文句。

不是保留連結 —— 連結要點開才知道。是把原句放在卡片裡， 讓「翻譯是否失真」可以當場被檢查，不必離開頁面。

這條與防線 1（無出處即拒收）互補：防線 1 管數字從哪來，防線 5 管數字有沒有被譯歪。

其他預設

  • goal: compress
  • regime: 豐沛（九個來源，每週多篇）→ 入選線 75、強化冗餘懲罰
  • cadence: weekly
  • 必問題：你要的是「全部掃過」還是「只看有實質進展的」？ —— 這決定入選線，是這個 profile 最重要的單一參數

二、research_frontier · 研究前沿（首個實例：RSI）

追 Recursive Self-Improvement (RSI) 的最新發展。

錨點

來源運算式類型
arXivsite:arxiv.org + cs.LG / cs.AI / cs.CLprimary
OpenReviewsite:openreview.netprimary
Semantic Scholarsite:semanticscholar.orgprimary
主要會議NeurIPS / ICML / ICLR proceedingsprimary
實驗室研究頁各 lab 的 research 而非 news 區primary
立場文章部落格、論壇position

硬規則：arXiv ID 必須驗證存在且標題相符

這是本專案已發生過一次的失敗換了外衣。harnessrouter.ai 那篇被撤回的文章， 之所以差點被採用，是因為它看起來完全合理。

一個編造的 arXiv ID 更危險 —— 它的格式天生可信（arXiv:2402.14207 這種形狀）， 而讀者幾乎不會去點。

每一篇被引用的論文，必須驗證 ID 真實存在、且該 ID 的標題與所述相符。 兩者其一不符即撤回該條，不降級。

（本專案首期引用的 STORM arXiv:2402.14207、HyDE 2212.10496、 Dense X 2309.02427 均屬此類，當時未逐一驗證 —— 補做。）

主張階梯（取代 verification 的新聞版三級）

新聞的 corroborated / unverified_claim / marketing 不適用於研究。研究要分的是證據層級：

值意義
reproduced有獨立複現
single_paper單篇論文結果，未見複現
theoretical理論分析或形式論證，無實驗
position立場文章、觀點，無新證據

RSI 這個題目特別容易被立場文章淹沒 —— 它牽涉 AGI 時程與安全立場， 討論量遠大於實證量。position 類必須明確標記且不得與 single_paper 混排。

其他預設

  • goal: compress（論文位置已知，難的是判斷哪篇真的推進了）
  • level: 預設 L5（研究前沿）
  • 推測允許但必須標記證據強度
  • 必問題：你關心的是能力進展、安全論證、還是時程判斷？ —— RSI 這三條線的來源與判準完全不同

三、career_lens · 不是 profile，是新的 purpose

「Science AI 與職涯研究的視角」—— 這裡的「視角」不是主題，是用途。

現有三種 purpose（decision / learning / monitoring）都不對： 它不是要做投資決定，不是補理解，也不只是盯著看。它問的是 「我該往哪裡移動」。

新增第四種 purpose：positioning。

purpose核心問題卡片必備欄位
decision什麼變化會推翻我的判斷delta_impact
monitoring有沒有漏掉重要動態—
learning我還不懂什麼術語解釋
positioning我該往哪裡移動skill_delta

skill_delta 欄位回答三件事：

  • 哪些能力正在升值（需求出現、工具還不成熟）
  • 哪些正在貶值（被自動化、被抽象掉）
  • 哪些研究方向在開或在關（新問題出現、舊問題被解掉）

時間尺度不同：positioning 關心的是季度趨勢，不是週變化。 所以 cadence 仍為 weekly（不漏訊號），但卡片的 skill_delta 必須 引用跨期累積的證據，不能只憑本週一則。 這是第一個需要跨期合成的 purpose —— state.json 從去重用途升級為趨勢證據來源。

五、待裁決

  1. vendor_watch 的入選線：要「全部掃過」（線壓到 40，每期 20+ 條） 還是「只看有實質進展的」（線拉到 75，每期 5–8 條）？ 這是這個 profile 最重要的單一參數，我需要你定。
  2. RSI 的三條線（能力進展／安全論證／時程判斷）要全收還是選一？ 全收的話卡片會混雜三種很不同的東西。
  3. Science AI 是獨立主題，還是 vendor_watch 的一個切面？ 我傾向獨立 —— 它的來源是期刊與研究機構，不是 AI 產品 blog， 而且 positioning 的跨期合成需求跟 vendor_watch 的週掃描節奏衝突。
