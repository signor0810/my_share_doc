Claude Code 的 Mod 功能：用程式碼改寫 Claude 的行為

Mod 是一種 Claude Code 外掛，用 JavaScript 或 TypeScript 寫成，在 Claude Code 自己的程序裡執行。它可以在 Claude 呼叫工具、你送出提示、畫面重繪的那一刻插手。這一版先講清楚每個 hook 在「一輪對話」裡的哪個時間點觸發，再列出完整的事件與 $ 介面清單。

01先建立直覺：hook 到底是什麼

Claude Code 平常做事的流程很固定：你送出提示，它組好系統提示，送給模型，模型決定呼叫工具，Claude Code 檢查權限，執行工具，把結果送回模型，重複到模型回答完為止。整個過程中畫面也不斷重繪。

Claude Code 每要做一件事之前，都會先發出一個事件，例如「我要執行 Bash 了」（tool.call）、「使用者按了 Enter」（prompt.submit）、「我要畫 spinner 了」（ui.render）。Hook 就是你登記在某個事件上的函式。事件發生時，Claude Code 會先呼叫你的函式，再決定要不要照原本的方式做。

用 EDA 的角度來看：這很像在 flow 的每個 step 前面插一個 pre-hook，或在訊號路徑上串進一級邏輯。訊號（事件 e）先經過你這一級，你可以讓它原樣通過、改掉它的值，或直接把它截斷，自己輸出一個結果。

事件 e 進入 ↓↑ 結果回傳
Mod A 的 hook
先看到事件，也最後拿到結果
Mod B 的 hook
A 呼叫 next(e) 才會輪到 B
Claude Code 自己的行為
真正執行工具、呼叫模型、畫出畫面

每個 hook 都長這樣：($, e, next) => 結果。

  • e：事件內容，唯讀。例如 tool.call 的 e.tool 是工具名稱，e.command 是 Bash 指令。
  • next(e)：交給下一層。最後一層是 Claude Code 本身，所以呼叫 next 才會「真的去做」。
  • $：你能用的所有能力（畫面、檔案、模型、計時器……），第 05 節列出全部。
你在 hook 裡做的事寫法Claude Code 的反應
觀察（Observe）return next(e)照常執行，你只是旁觀並記錄
事後處理const r = await next(e); …; return r先執行完，你再看結果做事
改寫（Rewrite）return next({ ...e, command: '…' })用你改過的內容去執行
攔截（Answer）return { deny: '原因' }，不呼叫 next完全不執行；Claude 讀到你給的原因

關鍵觀念：你寫的 hook 不是「定時跑」，也不是「Claude 想呼叫才跑」。它是 Claude Code 每走到時間線上的那個點時，自動、同步地先呼叫你，等你回覆才繼續。你的 hook 若遲遲不回，那個工具呼叫就一直暫停（有時間上限；等待 $.ui.ask 之類的使用者回應不計入）。

03把三個範例放回時間線上

上一版的範例只給了程式碼。下面用一個具體情境，逐步追蹤每個範例在什麼時刻被呼叫、收到什麼、回傳什麼。

範例一：擋下對 signoff 檔案的修改

import type { Register } from 'claude-code'

const SIGNOFF = /\.(sdc|spef|gds|oas)$|(^|\/)signoff\//

export const register: Register = on => {
  on('tool.call', { tool: ['Edit', 'Write'] }, ($, e, next) =>
    SIGNOFF.test(e.file_path)
      ? { deny: `${e.file_path} 是 signoff 檔案，禁止修改。請改提出建議讓使用者自行修改。` }
      : next(e),
  )
}

情境：你輸入「把 clock period 改成 2ns，順便更新 README」。

  1. prompt.submit你按下 Enter。這個 mod 沒登記此事件，所以不受影響。
  2. turn.stepClaude Code 把提示送給模型。
  3. tool.call (Grep)模型先搜尋 create_clock。篩選條件是 Edit/Write，Grep 不符合，hook 根本不會被呼叫。
  4. tool.call (Read)模型讀 constraints/top.sdc。同樣不符合，照常執行。
  5. tool.call (Edit)模型要改 constraints/top.sdc。hook 被呼叫，e.file_path 符合 .sdc，回傳 { deny }，沒有呼叫 next。權限提示不會出現，檔案沒被改。
  6. turn.step模型收到的工具結果就是你的 deny 文字，於是改成在回答裡告訴你該怎麼改。
  7. tool.call (Edit)模型改 README.md，regex 不符合，hook 呼叫 next(e)，接著才是一般權限流程與實際編輯。
  8. turn.complete這一輪結束。

所以這個 hook 的「上一層」就是：模型已經決定要改檔、Claude Code 正準備執行 Edit 工具、但還沒問你權限的那一瞬間。

範例二：改寫 Bash 指令並在狀態列顯示失敗

on('tool.call', { tool: 'Bash' }, async ($, e, next) => {
  const ran = await next({ ...e, command: e.command.trim() })   // ① 改寫後交出去，並等待
  const hasFailed = ran.deny === undefined && ran.isError === true   // ② 工具已執行完
  $.ui.status(hasFailed ? `failed: ${e.command.slice(0, 40)}` : undefined)
  return ran                                                    // ③ 結果交還給模型
})

情境：模型要跑 make sim，而模擬失敗。

  1. tool.call 進入hook 被呼叫，e.command 是 " make sim "。
  2. ① next(...)hook 把去掉空白的 "make sim" 交給下一層，然後在 await 停住。
  3. （引擎內部）PreToolUse hooks、權限檢查、你按下允許、Bash 實際執行 make sim，結束碼非 0。
  4. ② await 返回ran.isError 是 true，hook 把 failed: make sim 寫到狀態列。
  5. ③ return ran結果原封不動交回，模型照常看到錯誤訊息。

同一個函式在時間軸上跨了兩個點：await next() 之前的程式碼在工具執行前跑，之後的程式碼在工具執行後跑。這就是「洋蔥」的意思。

範例三：在輸入框上方顯示每輪耗時

這個 mod 需要多個事件合作，因為「一輪花多久」這件事橫跨整條時間線：

事件時間點這個 hook 做什麼
prompt.submit你按 Enter記下開始時間，工具計數歸零，然後 next(e) 放行
tool.call每次工具執行前計數 +1，next(e) 放行
turn.complete一輪結束算出秒數，用 update() 寫進 $.state；超過 120 秒就跳 toast
ui.render（AbovePrompt）每次要畫輸入框上方那一列讀 $.state，畫出「Last turn: 42s, 7 tool calls [Hide]」
ui.press（自動處理）你按下 Hide 按鈕按鈕的 onPress 把 isHidden 設為 true，畫面重繪後消失
 
import { atom, read, update } from 'claude-code'
import type { Register } from 'claude-code'

const last = atom({ plugin: 'turn-band', key: 'last' } as const, null)
const isHidden = atom({ plugin: 'turn-band', key: 'isHidden' } as const, false)

export const register: Register = on => {
  let startedAt = 0
  let tools = 0

  on('prompt.submit', async ($, e, next) => {
    startedAt = await $.clock.now()
    tools = 0
    return next(e)
  })

  on('tool.call', ($, e, next) => {
    tools += 1
    return next(e)
  })

  on('turn.complete', async ($, e, next) => {
    const seconds = Math.round(((await $.clock.now()) - startedAt) / 1000)
    await update($, last, () => ({ seconds, tools }))   // 寫入後，讀它的畫面自動重繪
    if (seconds > 120) $.ui.toast(`That turn took ${seconds}s`)
    return next(e)
  })

  on('ui.render', { component: 'AbovePrompt' }, async ($, e, next) => {
    const turn = await read($, last)
    if (e.props.hasSurvey || turn === null || (await read($, isHidden))) return next(e)
    const { Box, Button, Text } = $.ui.resolve(e)
    return (
      <Box>
        <Text dimColor>Last turn: {turn.seconds}s, {turn.tools} tool calls </Text>
        <Button key="hide" label="Hide" onPress={() => update($, isHidden, () => true)} />
      </Box>
    )
  })
}

這裡 ui.render 和其他三個事件不在同一條時間線上：前三個跟著對話流程走，ui.render 則是每當 Claude Code 要重畫那一塊時觸發。兩者之間靠 $.state 傳遞資料，update() 寫入時會通知畫面重繪。範例三需要的型別宣告檔 types/index.d.ts 見第 06 節。

Settings hook 事件（classic.*）

原本寫在 settings.json 的 hooks，其事件在 Mod 裡都能以 classic. 開頭攔截，e 就是那些 hook 從 stdin 收到的 JSON。共 33 個：

SessionStart · Setup · UserPromptSubmit · UserPromptExpansion · PreToolUse · PermissionRequest · PermissionDenied · PostToolUse · PostToolUseFailure · PostToolBatch · Notification · MessageDisplay · SubagentStart · SubagentStop · TaskCreated · TaskCompleted · Stop · StopFailure · TeammateIdle · InstructionsLoaded · ConfigChange · CwdChanged · DirectoryAdded · FileChanged · WorktreeCreate · WorktreeRemove · PreCompact · PostCompact · PreModelSwitch · PostModelSwitch · Elicitation · ElicitationResult · SessionEnd

說明見官方 Hooks reference。

$ 的每個呼叫本身也是事件

另外一層：$.fs.read()、$.process.run()、$.http.fetch() 等每一個 $ 呼叫，本身也是可被攔截的事件（如 on('http.fetch', …)）。這讓一個 mod 可以監管其他 mod 的行為，例如企業可以寫一個 mod 禁止其他 mod 連到特定網域。on('*', …) 則匹配所有事件。

篩選條件（matcher）

on('tool.call', { tool: 'Bash' }, hook)              // 單一值
on('tool.call', { tool: ['Edit', 'Write'] }, hook)    // 陣列：任一符合
on('tool.call', { tool: /^mcp__github__/ }, hook)    // 正規表示式
on('ui.render', { component: 'Spinner' }, hook)     // 只畫 spinner 時
on('classic.*', hook)                               // 所有 settings hook 事件

05引擎介面 $ 的完整清單

Mod 執行的環境沒有 Node、沒有 DOM，不能直接讀檔或連網。所有對外的事都要透過 $。這也是為什麼 claude plugin validate 能在安裝前列出一個 mod 會做哪些事。2.1.289 版共有 19 個 noun：

Noun用途常用方法

$.state這個 session 的共享值，熱重載後保留；寫入會觸發重繪get set（多半透過 atom / read / update）
$.store這個 mod 自己的鍵值儲存，跨 session 保留（JSON 檔）get set delete keys
$.session目前工作階段的資料：ID、工作目錄、git repo、對話內容、用量；也可壓縮、傳訊息給其他 sessionid cwd repo messages usage model
$.turn目前這一輪abort
$.prompt以使用者身分送出提示；讀寫輸入框read fill suggest
$.tool列出、執行工具；註冊模型可呼叫的新工具list register
$.command註冊與執行斜線指令list register
$.agent子代理類型list register
$.model用這個 session 的帳號額度呼叫模型complete classify fork
$.mcp呼叫已連線 MCP 伺服器的工具；連線 mod 自帶的伺服器call connect
$.fs檔案系統（相對路徑以工作目錄為準，UTF-8）read write list exists stat ancestors
$.process在本機執行指令（僅 CLI）run spawn
$.http網路請求fetch
$.clock時間與計時器now sleep after every
$.audio播放音效、語音play speak
$.config/config 選單的每一列，包含 mod 自己的設定list set
$.settings / $.env唯讀設定檔內容；環境變數read；get set
$.plugin / $.telemetry這個 mod 的名稱與目錄；遙測記錄name；log mark

每個方法的參數與範例，請看官方 Use the mods API，或你本機 mod 資料夾裡自動產生的 .claude-plugin/types/claude-code/index.d.ts。

安全提醒：Mod 不在沙箱裡，以你的權限執行，可以讀寫檔案、執行程式、連網、讀取環境變數裡的 API key，甚至在你被詢問前就核准工具呼叫。只安裝信任來源的 mod，安裝前先用 claude plugin validate 看它的 hooks: 和 calls:。

  • 版本需求：Claude Code v2.1.287 以上，預設開啟。
  • 請 Claude 寫：在對話中描述你要的功能，Claude 會寫好並詢問是否啟用熱重載；之後每輪結束自動重新載入。
  • 從資料夾載入：claude --plugin-dir ./turn-band。
  • 從 marketplace 安裝：/plugin install 名稱@marketplace。
  • 檢查：claude plugin validate、claude plugin test、claude --debug；/plugin 會顯示已載入幾個 mod。
  • 全部關閉：--safe-mode（單次），或 settings 中 "disableAllHooks": true。
各介面支援度不同：hook 在終端機、桌面版、VS Code、claude -p、雲端 session 都會執行，但 mod 畫的面板和資訊列只出現在終端機與桌面版的 Code 分頁。
