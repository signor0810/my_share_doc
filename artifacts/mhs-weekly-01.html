Anthropic 發布 Model Hardware Standard (MHS)：AI 代理操控實體儀器的統一介面

Anthropic 官方公告2026-08-27協議本體

Anthropic 與 HHMI Janelia Research Campus 共同發布 MHS。它要解決的問題是：實驗室與製造設備（液體處理器、顯微鏡、機械手臂）各用各家的封閉通訊協定，AI 代理要接上任一台都得寫專用的膠水程式碼 (glue code)，耗時數週到數月。MHS 提供一層通用抽象驅動，把控制收斂成 read 與 write 兩個原語；同時要求設備提供機器可讀的屬性清單 (machine-readable manifest)，主動宣告運動範圍、重量上限與安全邊界，讓代理在動作前能推理可行性。定位上它是 MCP (Model Context Protocol) 在實體硬體端的對應物 —— MCP 管軟體與 API，MHS 管儀器。目前為封閉研究預覽 (closed research preview)，邀請制。注意一個重要限制：規格尚未公開，有第三方開發者在嘗試對接時明確記錄「目前並無公開的 MHS 規格」。

既有標準組織查無 MHS 表態 —— SiLA 2 與 OPC UA LADS 皆未回應

標準組織查證（SiLA 2 官網）2026-09-26投資面

實驗室儀器通訊早已存在開放標準：SiLA 2（基於 gRPC，負責毫秒級的機器對機器命令執行）與 OPC UA LADS（IEC 63339，提供製造商無關的設備資料模型與可追溯性）。MHS 與它們是共存還是取代，直接決定投資論述 —— 若共存（MHS 當代理語意層、SiLA／LADS 當設備層），既有廠商的軟體護城河受損有限；若取代，封閉工作流程軟體的加價能力會被侵蝕，利益轉向原生硬體出貨商。本期查證結果：兩個組織的官網皆查無任何提及 MHS 或 Anthropic 的內容。這是「查無」而非「已排除」——可能只是太早，也可能它們不視其為威脅。本期特別記錄此空白，因為它是後續最值得盯的單一訊號：任一組織的首次表態，情報價值高於任何媒體報導。

前期技術：MHS 之前已有人用 MCP 做代理對儀器的控制（Opentrons × HighRes）

Opentrons 新聞稿2026-02-04協議本體

本則**不是 MHS 採用證據**，全文並未出現 MHS 或 Model Hardware Standard —— 收錄為前期技術 (prior art) 對照。2026 年 2 月，開源實驗室機器人商 Opentrons 與編排平台廠 HighRes 在 SLAS 2026 展示：以 Opentrons 的 MCP Server 搭配 Python Protocol API，由軟體代理自主生成並執行 qPCR 工作流，串聯 Opentrons Flex 與 Cellario。意義在於 MHS 出現前六個月，就已經有人用 MCP 直接做代理對儀器的控制。這說明 MHS 要證明的不是「代理能操控儀器」（已被做到），而是「不必為每家設備寫專用整合」。判斷 MHS 價值時，這是正確的對照基準。
