這個助手是什麼

目的：下一次找旅遊資訊時，幾分鐘內拿到一份可信的草稿。

記得你們
家庭成員的約束（4 歲、午睡、不吃辣、怕人多、室內優先）存成資料，每次規劃自動套用，不用重講。
不亂編
每個營業時間、地址、班次都標 ✅／🟡／❌。AI 搜尋助手（agy）的數字一律複驗——今天就擋下了一家查無來源的餐廳。
越用越準
去過的地方、踩過的坑、實際車程都存進知識庫。回來後匯出 Google 地圖時間軸，就能自動對照「計畫 vs 實際」。
為什麼強調查證：學術研究（TravelPlanner, ICML 2024）中 GPT-4 在帶限制的真實旅遊規劃只有 0.6% 完全正確。本專案的台南行程也實際出現過「班車根本不停那站」的錯誤。

一趟旅程的完整生命週期

  1. 說需求：「今天下午從廣豐出發，2–3 小時，找晚餐和小孩玩的地方」
  2. Claude 讀記憶：成員約束、在地陷阱、已知地點（今天就直接用到了玩具圖書館）
  3. 派 agy 搜尋：廣度找候選，Claude 只複驗會放進行程的那幾個
  4. 寫草稿 trips/<日期_名稱>/plan.md，每個關鍵事實附 ✅／🟡／❌
  5. 過閘門：約束有沒有違反、事實有沒有沒查的
  6. 出發：手機的 Google 地圖時間軸開著就好，什麼都不用記
  7. 回來：匯出時間軸 → ingest.py → 自動產生「計畫 vs 實際」
  8. 學到的寫回知識庫：實際車程、停留時間、新地點、新陷阱（你同意才寫入）

三個你一定會看到的格式

① 信心標記
  • ✅ 兩個以上獨立來源吻合
  • 🟡 單一來源（附網址）
  • ❌ 查不到——照實寫，不猜
② 三態值（成員、地點欄位）
  • 有值 已登錄
  • null 未知 → 閘門判 ❌，不當作「沒限制」
  • false / [] 確認不需要
③ claim 標記（行程裡） 
<!-- claim:hours name="壽司郎 八德置地店"
  addr="…728號1樓" open=11:00 close=22:00 -->
寫在事實的下一行，告訴閘門要查什麼。

以後怎麼記錄旅程

原則：旅途中什麼都不用記。位置與時間交給手機，回來後一句話回填。

出發前（一次性設定）

確認手機 Google 地圖時間軸是開的：設定 → 位置 → 定位服務 → 時間軸。

回來後

  1. 同一個畫面點 匯出時間軸資料，存到雲端硬碟 我的雲端硬碟 / 0_Travel / trips / _timeline /，檔名用 時間軸_YYYY-MM-DD.json（匯出日）
  2. 跟 Claude 說「時間軸放好了，回填 <哪一趟>」
  3. Claude 跑 ingest.py：切出那幾天、反查地名、比對地點庫，寫出 actual.md
  4. Claude 列出建議（實際車程、停留時間、新地點），你說「套用」才寫進知識庫
  5. 有空再口頭補一句「好不好玩、人多不多、好不好吃」——這是唯一機器查不到的東西
隱私規則（程式強制）：家、常去地點、過夜地點的座標不送外部服務、不寫進檔案。時間軸檔含完整位置歷史，只放在本資料夾，不外傳。

時間軸做得到／做不到

做得到做不到
每段車程實際幾分鐘、幾公里為什麼停那麼久（逛街？排隊？）——不會自行推測
每個地點停留多久、在哪裡加油這類幾分鐘的短停留可能偵測不到
計畫中的時刻準不準小孩什麼時候開始鬧（未來可加「小孩狀態」一鍵表單）

增加新的程式功能（開發者）

  • 新的查證類型（例如接 Google Places 查營業時間）：在 tools/validator/ 加 verifier，對應 RULES.md 的 claim 類型表；規格見 docs/閘門規格_v1.md
  • 新的回填來源（例如照片 EXIF 時間）：在 tools/timeline.py 旁加解析器，輸出同樣的 log.jsonl 事件格式
  • 先寫測試：tools/tests/ 用固定的假資料，不讀真實 members/knowledge；改完跑 pytest 必須全綠
  • 相依套件：只用 Python 3.13 + pyyaml、requests；所有檔案讀寫顯式 UTF-8
